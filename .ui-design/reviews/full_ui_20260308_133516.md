## Summary

The app has a solid dark-mode aesthetic with good typographic choices (IBM Plex) and consistent use of zinc tones. The main issues are: one silent bug where the API key warning always shows regardless of key presence, stale copy in two places that still refers to CSV-only upload, and several code duplication points (MiniBarChart, BANK_TABS) that will diverge if not consolidated. The insight card firing a Sonnet API call on every page visit is the biggest performance concern.

## Critical Issues

### Issue 1: API key warning always renders

**Severity:** Critical
**Location:** `app/upload/page.tsx:42,111`
**Category:** Code / Usability

**Problem:**
`missingApiKey` is computed from `process.env.NEXT_PUBLIC_HAS_ANTHROPIC_KEY` but the JSX warning banner at line 111 is always rendered — it's never wrapped in `{missingApiKey && ...}`. The `missingApiKey` variable is dead code.

**Impact:**
Users who have set the API key always see a yellow warning telling them to set the API key. It creates false anxiety and erodes trust in the upload flow.

**Recommendation:**
Wrap the warning banner in the computed boolean:

```tsx
// Before (line 111)
<div className="rounded-lg border border-yellow-500/40 bg-yellow-500/10 ...">
  <strong>Note:</strong> Set <code>ANTHROPIC_API_KEY</code>...
</div>

// After
{missingApiKey && (
  <div className="rounded-lg border border-yellow-500/40 bg-yellow-500/10 ...">
    <strong>Note:</strong> Set <code>ANTHROPIC_API_KEY</code>...
  </div>
)}
```

## Major Issues

### Issue 3: InsightCard fires Claude API call on every page visit

**Severity:** Major
**Location:** `components/InsightCard.tsx:15-27`
**Category:** Performance

**Problem:**
The `useEffect` fetches `/api/insight` on every mount. Each call takes 2–5s and costs tokens. There is no caching layer.

**Impact:**
Every navigation back to the home page triggers a Sonnet call. With typical usage (visiting home multiple times per session) this adds significant latency and unnecessary API costs.

**Recommendation:**
Cache the result in `sessionStorage` with a TTL. Re-use the cached value within the same browser session:

```tsx
const CACHE_KEY = 'insight_cache'
const CACHE_TTL_MS = 30 * 60 * 1000 // 30 min

useEffect(() => {
  if (!hasTransactions) return
  const cached = sessionStorage.getItem(CACHE_KEY)
  if (cached) {
    const { text, ts } = JSON.parse(cached)
    if (Date.now() - ts < CACHE_TTL_MS) { setText(text); return }
  }
  setLoading(true)
  fetch('/api/insight', { method: 'POST' })
    .then(r => r.json())
    .then(d => {
      if (!d.error) {
        setText(d.text)
        sessionStorage.setItem(CACHE_KEY, JSON.stringify({ text: d.text, ts: Date.now() }))
      } else setError(true)
    })
    .catch(() => setError(true))
    .finally(() => setLoading(false))
}, [hasTransactions])
```

### Issue 5: BANK_TABS constant duplicated

**Severity:** Major
**Location:** `app/page.tsx:37`, `app/insights/page.tsx:47`
**Category:** Code Quality

**Problem:**
Both pages define `const BANK_TABS = ['all', ...BANKS] as const`. If a bank is added, the constant stays in sync automatically (since it derives from `BANKS`), but the type definition and the wrapping in a constant is duplicated.

**Recommendation:**
Move to `lib/display.ts` or `lib/schema.ts`:
```ts

export type BankTab = (typeof BANK_TABS)[number]
```

### Issue 13: handleSubmit keyboard handler uses unsafe cast

**Severity:** Minor
**Location:** `app/ask/page.tsx:246`
**Category:** Code Quality

**Problem:**
```tsx
handleSubmit(e as unknown as React.FormEvent)
```
This bypasses TypeScript's type system. The `KeyboardEvent` is cast to `FormEvent` to call `preventDefault()`.

**Recommendation:**
Call `e.preventDefault()` directly and invoke submit logic separately:
```tsx
onKeyDown={e => {
  if (e.key === 'Enter' && !e.shiftKey) {
    e.preventDefault()
    if (question.trim() && !submitting) handleSubmitQuestion(question)
  }
}}
```

The bank selector gives no hint that UOB requires PDF while others use CSV. A small note per bank in the select or a static help text line would prevent confusion:
